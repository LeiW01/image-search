# 双模型服饰图片检索设计

## 1. 一次搜索经历什么

```text
上传查询图片
  ↓
统一转成 RGB
  ↓
同时生成 pHash、DINOv2 向量、FashionSigLIP 向量
  ↓
Qdrant 分别从 dino 和 fashion 向量空间召回候选图片
  ↓
合并候选，计算两种余弦相似度与 pHash 汉明距离
  ↓
校准器计算“同款概率”
  ↓
按 店铺ID:商品ID 聚合，保留每个商品的最佳展示图
  ↓
先输出高置信同款，再输出去重后的相似款
```

## 2. 为什么需要两个大模型

DINOv2 和 FashionSigLIP 看到的是不同层面的相似性。

DINOv2 更敏感于视觉结构和细节。例如两只鞋是否具有相同鞋底、鞋面拼接和轮廓，或者两个包是否具有相同包型、提手和五金位置。因此它适合同款候选召回，但它并不知道“这是通勤风黑色皮包”这样的服饰语义。

FashionSigLIP 在服饰数据上经过针对性训练，更擅长品类、颜色、材质和风格。即使商品不是同款，它仍能找到用户可能愿意购买的相似商品。因此它适合相似款排序。

两个分数不能简单地当作同一件事。第一版让校准器结合：

```text
FashionSigLIP 余弦相似度
DINOv2 余弦相似度
pHash 相似度
```

输出同款概率。相似款则使用可调权重：

```text
相似分数 = FashionSigLIP权重 × FashionSigLIP分数
         + (1 - FashionSigLIP权重) × DINOv2分数
```

默认 FashionSigLIP 权重为 `0.8`，最后应以自动评测和人工观察为准。

## 3. 为什么还需要 pHash

大模型向量检索很强，但对“原图被重新压缩或轻微改尺寸”的判断不如专门的感知哈希直接。pHash 只需要 64 bit，汉明距离为 0 表示两张图的指纹完全相同，距离越小越可能是近重复图。

pHash 不能独立判断换角度、换背景或模特上身图是不是同款，所以它只是同款判断的一个强特征。

## 4. 数据如何保存

Qdrant 中每张 `display` 图片对应一个 point：

```text
point id：由相对路径生成的稳定 UUID

命名向量：
  fashion：768维、cosine
  dino：768维、cosine

payload：
  image_id
  shop_id
  product_id
  product_key
  relative_path
  phash
  文件大小、修改时间、内容摘要
  两个模型的固定 revision
```

内容摘要和模型 revision 用于增量索引：图片内容与模型版本都没变时直接跳过；原图被删除时同步删除 Qdrant point。

## 5. 如何自动学习同款阈值

同一个 `product_key` 下的不同展示图天然是正样本，不同商品的图片是负样本。程序用这些样本训练一个很小的逻辑回归分类器，而不是重新训练 DINOv2 或 FashionSigLIP。

阈值选择以精确率为先，目标为 0.95。达不到可靠精度时允许“同款”区域为空，不能把普通相似款伪装成同款。

## 6. 自动评测如何避免作弊

只评测至少有两张展示图的商品。每次拿出一张作为查询图，并用 `image_id` 排除查询图片本身，再检查同商品的其他图片能否进入商品级 Top 1、Top 5 和 Top 10。

程序比较六种配置：FashionSigLIP、DINOv2、融合 0.5、0.7、0.8 和 0.9，同时记录 p50、p95 查询耗时。

## 7. 本机资源与预计耗时

M1 Pro 优先使用 MPS；遇到不兼容算子时编码器会自动退回 CPU 重试。16 GB 内存下默认批量为 16，发生批量推理错误时索引器会缩小批次，单张损坏图片只记录错误，不中断整个任务。

2026-07-17 实测目录中有 37,874 张展示图。首次建索引需要下载模型并逐图推理，耗时主要取决于网络、图片尺寸和 MPS 实际速度。第二次运行会跳过未变化图片，明显更快。

## 8. 安全边界

- 只读取商品展示图，不修改原图。
- 模型均为公开权重，不需要 Hugging Face Token。
- FashionSigLIP 通过 OpenCLIP 与 safetensors 加载，不执行远程 Python 代码。
- Gradio 固定监听 `127.0.0.1`，`share=False`。
- 图片、向量数据库、校准器和评测结果全部留在本机。
